# Colaborar con PoetisA

Puedes contribuir sin programar: proponer bibliotecas, verificar fuentes, cotejar versos, describir problemas de accesibilidad o probar la app en distintos equipos.

## Un cambio a la vez

1. Abre una propuesta en Issues. Para nuevos textos, usa la plantilla de colección y enlaza edición y derechos.
2. Para código, crea un fork y una rama con un propósito concreto.
3. No incluyas claves, datos de cuentas, correos de lectores ni cuadernos.
4. Ejecuta `npm test`, `npm run check:catalog` y `npm run build`.
5. Abre un pull request explicando problema, cambio y comprobaciones. Para interfaz, incluye capturas sin información personal.

Los aportes al código y documentación original se presentan bajo MIT. Para textos de terceros se requiere su propia base de uso; MIT no sustituye ese permiso.

## Criterios editoriales

- Reproduce fielmente el poema; mantén separada la interpretación de IA.
- Conserva tildes, versos y estrofas. Documenta cualquier modernización.
- Atribuye autoría, libro, año, edición y páginas.
- Enlaza la fuente y la ficha de derechos; comprueba la edición y el ámbito territorial.
- No añadas prólogos, traducciones, imágenes o notas protegidas junto al poema.
- No importes masivamente ni raspes bibliotecas sin revisar sus condiciones.
- No conviertas las palabras del lector en un diagnóstico ni prometas resultados terapéuticos.

Los mantenedores revisan código y contenido antes de integrarlos. Para vulnerabilidades usa el canal privado de SECURITY.md.

## Convivencia

Respeta a quienes participan, cita fuentes, da crédito y acepta correcciones. No se aceptan acoso, discriminación ni publicación de datos personales ajenos.
